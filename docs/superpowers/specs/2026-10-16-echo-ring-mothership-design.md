# Echo Ring Mothership — Design Spec

**Date:** 2026-10-16
**Status:** Draft for review
**Path:** architectural (new renderer module + new menu surface)

## Summary

Replace the current saucer mothership with a procedurally-drawn **segmented ring station**, and
make it the visual centerpiece of both the main menu and the gameplay arena.

Today the main menu covers the gameplay canvas with `rgba(2,4,8,.92)` + `blur(12px)`, so no
mothership is visible while the player is in the menu. This spec introduces a second canvas behind
the menu overlay and a single shared renderer used by both surfaces, so the menu ship and the
in-run ship can never drift apart.

## Decisions

Settled through visual comparison in the brainstorming companion. All three comparison screens
(silhouette, menu composition, hull detail) are persisted under
`.superpowers/brainstorm/mothership-20261016-160923/content/`.

| Decision | Choice | Rationale |
|---|---|---|
| Silhouette | **Echo Ring** — segmented halo | Most animated potential; ties to the game name; distinct from the current saucer |
| Ring center | **Energy membrane** | Keeps the open-ring read but looks solid; gives a hit-flare surface |
| Menu composition | **Halo backdrop** | Ring bleeds off-edge at ~50% opacity, console floats above. Cheapest, most cinematic |
| Motion (menu) | **Counter-rotating** | Ring 44s CW, hub 26s CCW — reads as an engineered gear train |
| Motion (runs) | **Co-rotating** | Whole ring 52s — calmer, clearer when 200 enemies are on screen |
| Hull detail | **Plated Carrier (A) + Habitat windows (B)** | A's armour plate banding / bevels / nozzles for structure, B's warm lit window rows for inhabited scale |

Explicitly rejected: vertical dagger (too narrow for arena presence), wide manta (wings clip
enemies), solid-filled ring (kills the halo), 90% opaque menu overlay (hides the ship), locked
motion in the menu (reads as background art).

## Architecture

### New module: `src/game/mothership.ts`

Single owner of all ring drawing.

```ts
export type RingMotion = 'counter' | 'co' | 'locked';
export interface MothershipOpts {
  r: number;            // outer radius in px
  hpFrac: number;       // 0..1
  t: number;            // ms timestamp for animation phase
  motion: RingMotion;
  detail?: 'full' | 'lite';  // auto-selected from r if omitted
  hitFlash?: number;         // 0..1, decays after each impact
  hitAngle?: number;         // radians, where the impact landed
}
export function drawMothership(ctx: CanvasRenderingContext2D, x: number, y: number, o: MothershipOpts): void;
```

All geometry is authored in a normalized **200×200 space** and scaled by `r / 58`, so the same code
draws the 54px in-run ring and the full-bleed menu hero. Nothing in the module touches the DOM.

### Detail tiering

Micro-detail only exists above a pixel threshold. When `r < 40`, the renderer automatically drops
to the `lite` path — band, membrane, windows, nozzles, core — and skips panel ticks, vents,
docking collars, spokes and bevels. This is what keeps the ship legible at 108px instead of
turning into grey mush.

Thresholds live in one exported constant (`DETAIL_MIN_R`) so they are tuned in one place.

### Menu surface

- **New** `<canvas id="menu-ship">` inside the menu overlay, generated by `scripts/gen_index.py`
  (never hand-edit `index.html` — it is regenerated).
- Positioned `position:absolute; inset:0`. The ring radius is computed as
  `max(vw, vh) * 0.5 / 0.58` so the drawn ring diameter (2 × r) always exceeds the viewport's
  larger dimension — guaranteeing the ring is cropped by all four edges on any aspect ratio.
  Clamp to a minimum of 320px so small windows do not produce a tiny ship.
- Opacity `0.5`; draws only while `phase === 'menu'`, leaving the gameplay canvas untouched.

A second canvas was chosen over relocating `#game` across DOM parents, which would require
restyling on every phase change.

### Overlay transparency

`#menu-overlay` background goes from `rgba(2,4,8,.92)` to a light vignette
(`rgba(2,4,8,.25)` → transparent radial) and `backdrop-filter` blur is removed. The menu panel keeps
its own glass background, so **text contrast is unchanged**.

### Reduced motion

`prefers-reduced-motion: reduce` forces `motion: 'locked'` in both surfaces. The membrane and core
keep breathing so the ship never appears dead. Read once via `matchMedia` at startup and stored in
a module-level flag.

## Rendering detail

Draw order, back to front:

1. **Membrane** — translucent radial field across the gap, with a dashed rim
2. **Radiator fins** — translucent rectangles behind the ring at the cardinals
3. **Ring band** — 4 arcs via `stroke-dasharray`, gaps centred on the diagonals
4. **Panel ticks** — thin radial dividers across each band (full detail only)
5. **Vents** — dark slots along the outer band (full detail only)
6. **Window row** — warm lit dashes (`#fef3c7`) on the inner edge; the primary "crewed" signal
7. **Hull bevels** — outer highlight + inner shadow lines
8. **Spokes** — truss lines hub→ring on the diagonals (full detail only)
9. **Engine nozzles** — flared trapezoids at the cardinals, with cyan glow and a core highlight
10. **Core hub** — hard octagon, dome, and bright centre

### Hull feedback

`hpFrac` drives:

| Threshold | Effect |
|---|---|
| any | Core brightness and membrane opacity scale with hull |
| < 0.50 | Teal rim shifts amber |
| < 0.25 | Rim shifts red; membrane flicker increases |
| on hit | `hitFlash` flares the membrane at the impact angle |

## Testing

1. **Pure geometry** — dasharray segment math is deterministic and DOM-free; unit test asserts the
   4-gaps-on-diagonals property and that arc lengths sum to the circumference.
2. **Renderer robustness** — DOM-stub test calls `drawMothership` across `hpFrac` ∈ {0, 0.25, 0.5,
   1} × `motion` ∈ {counter, co, locked} × `detail` ∈ {full, lite} and asserts no throw.
3. **Menu surface** — asserts `#menu-ship` exists after generation and that the menu draw path
   does not throw.
4. **Regression** — existing fx/combat/render tests unchanged; economy sim still lands wall wave 50.

Verification gate: `npm test` (which now runs `tsc --noEmit` first — this was added after a lost
import shipped through a green build), then `npm run build`, then `node scripts/sim.mjs`.

## Risks

- **Detail mush at 108px** — mitigated by the `lite` tier; must be confirmed visually in-browser.
- **Overlay readability** — lowering opacity could hurt text contrast; mitigated by keeping the
  panel's own glass background and verifying contrast after the change.
- **Browser QA gap** — `agent-browser` is unavailable in this environment
  (`Unknown: ChildProcess.kill`), so final visual confirmation is manual.
- **Golden-layout regressions** — `index.html` is generated; any hand-edit is lost on the next
  `gen_index.py` run.
