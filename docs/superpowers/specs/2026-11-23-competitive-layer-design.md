# Echo Spire — Competitive Layer Design

> Status: draft for review. Implements the market-competitiveness audit dated 2026-11-23.
> First implementation plan: `docs/superpowers/plans/2026-11-23-competitive-layer.md`.

## Intent / why

Echo Spire has a strong systems backbone (deep economy, 33 research lines, procedural
art, 142 tests) but almost nothing that makes a player *return* or *compete*: the
leaderboard is a five-line `console.info` stub, there is no daily structure, and
nothing is shareable. The game's one genuinely ownable idea — the Echo, a ghost of a
past run — is currently only a DPS constant in `src/game/echo.ts` (`echoDps()` returns
`recorded * 0.15`), not a replay. This design turns that idea into the product's moat:
**every run leaves a real ghost, and you race other people's ghosts.**

Win condition for this phase: a player can (1) launch a daily run with identical
conditions to everyone else that day, (2) see and race a ghost of another run beside
their mothership, (3) put their own run on a board, and (4) share a good run as an
image — all with zero backend configured.

## Goals

- A deterministic run mode whose spawn/crit/surge randomness comes from a seed, not
  `Math.random`, so a date is a fair shared "course."
- A compact, serializable ghost trace recorded from a run and replayed visually.
- A leaderboard client that works offline first (local board + seeded demo ghosts)
  and switches to a real HTTP backend via one env var.
- One-tap run-card sharing with a graceful download fallback.
- All of the above must remain playable with no network and with reduced motion.

## Non-goals

- No accounts, logins, real-money payments, or server-side anti-cheat in this phase.
- No seasons, quests, battle pass, clans, or Hall of Echoes yet (Phase 2).
- No archetypes, command-deck abilities, boss patterns, or audio yet (Phase 3).
- No cloud save, PWA install flow, or analytics yet (Phase 4).

## Anti-goals (what would make this a failure even if it works)

- A "ghost" that is just a stat number — it must be visibly present in the arena.
- A daily run where two players face different RNG streams.
- Requiring a backend to see the feature; an empty board on first launch feels dead.
- Breaking the v2 save contract or invalidating the 142-test baseline.
- Making cosmetic-only fx deterministic — that would cost performance for no fairness.

## Constraints (inherited, verbatim where applicable)

- All tuning numbers live in `src/sim/balance.ts` (project Global Constraint). New
  constants for this feature (`GHOST_SAMPLE_MS`, board limits) go there.
- `SAVE_VERSION = 2`, key `echospire.save.v1`; v1 payloads refuse to load. New
  save fields are optional and backward-compatible; no version bump in this phase.
- TypeScript strict; ESM imports use `.js` specifiers.
- Verification is `npm test` = `npm run typecheck && vitest run`; baseline 142 tests.
- `npm run build` and `node scripts/sim.mjs` must stay green.
- `src/style.css` and `index.html` are generated by `scripts/gen_css.py` and
  `scripts/gen_index.py` — change the generators, then regenerate; never hand-edit
  generated id lists.
- `prefers-reduced-motion` must remain respected; no image assets, canvas only.
- Offline-first: network is an enhancement, selected by `VITE_LEADERBOARD_URL`.

## Approaches considered

1. **Content-first (seasons / quests / pass).** Highest retention ceiling but needs
   live ops and a content pipeline; weak first impression without a social layer.
2. **Craft-first (archetypes, active skills, boss patterns).** Improves the game, but
   a better single-player game without a reason to return still churns.
3. **Social-first (async ghosts + daily seed + share cards) — CHOSEN.** Reuses the
   Echo identity and the leaderboard stub, creates both a habit (daily) and a
   distribution loop (shareable cards), and is the only option that gives the game a
   claim no competitor owns. Trades off: needs a small backend eventually and careful
   determinism work now.

Chosen scope for the first plan: **Phase 1 — Competitive Layer**, tasks 1–9 in the
linked plan. This is one independent, testable subsystem.

## Decided design

- **Seeded RNG.** `nextRandom(s: { rngState?: number }): number` (mulberry32 step)
  advances a numeric `rngState` on GameState. Replace the four gameplay `Math.random`
  call sites (`spawning.ts:10`, `update.ts:49`, `update.ts:52`, `update.ts:68`).
  Cosmetic fx randomness in `render.ts` (screen shake, sparks) stays `Math.random`.
- **Daily seed.** `seedFromString('echo-spire:' + YYYY-MM-DD)` in UTC; stored as
  `s.seed`, mode as `s.mode`. Normal runs seed from `Date.now()`.
- **Ghost trace.** Samples at `GHOST_SAMPLE_MS = 500` of *sim time* (`s.timeS`, not
  wall clock, so x2/x4 playback stays aligned): `[tMs, wave, hullFrac, dmg, kills]`.
  `ghostAt(trace, t)` linearly interpolates. Budget ≤ 64KB for a 10-minute run.
- **Leaderboard.** `LeaderboardClient` interface with `localClient()` (localStorage +
  three named demo ghosts so the board is never empty) and `httpClient(baseUrl)`;
  `clientFromEnv()` picks by `VITE_LEADERBOARD_URL`. A cheap deterministic `entryHash`
  deters casual tampering only — it is explicitly not security.
- **Rendering.** The ghost ring draws at the free arena corner (490, 470), scaled to
  `r = 28`, translucent violet, with its hull fraction from `ghostAt()`. A topbar pill
  shows the ghost's wave/kills delta.
- **Share card.** Canvas-generated PNG reusing the project's fonts; Web Share API
  with file fallback to download.

## Roadmap (future plans, one subsystem each)

- **Phase 2 — Retention:** daily contracts + streaks, "Hall of Echoes" collectible
  deaths, 6-week Season of the Rift (free/premium cosmetic pass).
- **Phase 3 — Craft:** augment set bonuses ("Chain Storm"), three mothership
  archetypes, telegraphed boss patterns, 2–3 active command abilities, lab
  constellation visualization, procedural WebAudio score.
- **Phase 4 — Distribution & money:** PWA install/offline, anonymous cloud save,
  privacy-friendly funnel analytics, cosmetic Hangar + respectful rewarded ads.
- **Phase 5 — Cleanup:** reconcile the stale `design-system/echo-spire/MASTER.md`
  (currently green/gold "card & board" with 3D language) with the shipped amber/gold
  neon UI; fix responsive layout for 375px.

## What's left to the builder

Nothing in Phase 1 beyond the decisions above: file boundaries, exact signatures,
constants, and tests are pinned in the implementation plan. Demo-ghost names and the
run-card copy are fixed there for consistency.
